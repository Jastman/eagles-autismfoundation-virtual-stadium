# Risk Register — Stadium Asset & Packaging

**Last updated:** 2026-09-28 (Phase 0, cycle 2)

| ID | Risk | Severity | Owner | Mitigation | Ship Impact |
|---|---|---|---|---|---|
| AR1 | Asset license ambiguity: vendor is unclear (CGTrader vs. 3dmodels.org, F11), and license terms for UE packaging / kiosk redistribution are unconfirmed. | High | Legal + Product | Obtain signed license from confirmed vendor; verify mod/redistribution rights explicitly. Document approval in ASSET_INGESTION.md gate. If terms prohibit packaging, use placeholder or licensed alternative. | **BLOCKS SHIP** — cannot package without verified redistribution rights. |
| AR2 | Asset not delivered; no timeline or fallback plan. | High | Procurement | Asset ingestion SOP gates on receipt. Proxy stadium placeholder is complete and functional; keep it as demo default until asset is validated. | Use proxy for Oct 9 demo; ship real asset only if approved by Gate 2 checkpoint (model imports, baseline perf confirmed). |
| AR3 | Model topology & performance unknown: 1.836M polys could exceed 30 FPS target on target hardware. No poly budget, LOD strategy, or Nanite suitability confirmed. | High | Engineering | Execute ASSET_INGESTION.md Step 4 & Perf Baseline. Measure draw calls, memory on target hardware. If over-budget, reduce poly count (mesh decimation, LOD gen, bake details to normal maps) or revert to proxy. | Test before commit; establish hard frame-time SLA. |
| AR4 | Trademark/brand use: asset may contain baked-in Eagles marks, "Lincoln Financial Field" naming, or sponsor signage (Nike, Bud Light, etc.) that require approval or removal. | Medium | Legal | Before import, visually inspect the model (screenshots from vendor); flag any baked branding. Store findings in risk register. If marks are present, obtain Eagles/sponsor approval or neutralize textures. Recommend texture-based redaction (Substance Designer) rather than geometry deletion. | Ship only if marks are approved or removed. Default: use proxy. |
| AR5 | Cesium ion token exposure in packaged build: token could be embedded in config or hardcoded; public display could leak credentials and burn quota. | Medium-High | Security + DevOps | VERIFY: how Cesium stores tokens (environment variable, config file, C++ constant?). For the packaged demo: either disable Cesium imagery (use local/cached tiles), or use a time-limited public token with read-only, scoped permissions. Never commit plaintext tokens. Use `DefaultEngine.ini` with a placeholder `$(TOKEN_ENV)` and inject at build time. | **DO NOT SHIP** with plaintext token. Scope tokens to demo account; rotate after Oct 9. |
| AR6 | Google Photorealistic 3D Tiles or imagery licensing: if the demo uses Google geospatial data (via Cesium partnership), attribution and terms of use must be verified and displayed. | Medium | Legal | If using Google tiles: VERIFY attribution requirements in on-screen credit or splash screen. Check Cesium for Unreal documentation for Google-specific settings. Obtain written confirmation that Cesium handles licensing. | Include visible attribution on the demo UX. If unconfirmed, disable Google tiles and use public alternatives. |
| AR7 | No .gitattributes / Git LFS: repo can't handle binary assets cleanly; large files bloat clone size and complicate branching. | Medium | DevOps | Create `.gitattributes` to exclude `/Game/LFF/Assets/Stadium/Imported/**` from git. Keep untouched vendor source outside the repo (durable archive drive plus team backup, never a temp directory). Store only optimized, deduplicated assets in git. Use `git lfs install && git lfs track "*.uasset"` if asset becomes persistent. | Don't commit raw FBX/glTF. Archive source separately; version optimized assets only. |
| AR8 | No interior data (concourse, restrooms, sensory room): if the purchased asset lacks interior geometry, placeholders may be mistaken for real navigation. | Medium | Product + Accessibility | ASSUMPTION A4: all interior stops are clearly marked "Illustrative." Add a mandatory on-screen banner (red/yellow) on every interior step. Include a disclaimer widget. Test with accessibility advisors. | Interior steps must state "Not a real map" clearly. Defer to Gate 7 (stakeholder approval). |
| AR9 | Unreal MCP experimental status: tool names, schemas, or behavior may change; breaking changes could halt local builds mid-project. | Medium | Engineering | D5: rely on CLI-reproducible evidence (logs, binaries), not MCP-only workflows. Document every gate with a shell script and build log. MCP is optional acceleration; CLI is the source of truth. | Gate completeness depends on CLI verification, not MCP. |
| AR10 | Packaging on Linux container: container has no UE5.8 engine, Blender, or .NET; can't compile, package, or run the app. All asset integration and validation must happen on the engine workstation. | High | Infrastructure | Use LOCAL_AGENT_SETUP.md workflow: cloud session handles code/config/docs; engine workstation handles compile, package, and asset import via MCP or CLI. Document exact commands for reproducibility. | Cloud session can't verify packaging; requires manual sign-off on the workstation. Gate 6 (packaging) must include build logs. |
| AR11 | Cesium georeference drift: if the local origin shifts during development, stored world positions in `StadiumScheduleStop` become stale (R4, F5). | Medium | Architecture | D1: establish one fixed local origin at the stadium; store it in a pinned Data Asset (`DA_CesiumOrigin`). Steps reference named targets, not raw coords. Add a migration script for any origin change. | Position all steps before any code depends on them. Lock origin in Gate 3 checkpoint. |
| AR12 | Placeholder copy / branding unapproved: placeholder text, labels, or UI claims about the stadium may be inaccurate or offend stakeholders. | Low-Medium | Product | ASSUMPTION A5: all placeholder text is reviewed by Eagles Autism Foundation and accessibility advisors. Maintain a copy matrix in `/Docs/PlaceholderApprovals.md`. Get written sign-off before shipping. | Defer to Gate 7. Use neutral, descriptive labels until approved. |

**Legend:**
- **BLOCKS SHIP:** risk must be resolved (not just mitigated) before packaging.
- **DO NOT SHIP:** explicit mandate; do not package with current state.
- **Defer to [Gate]:** risk is addressed in the quality gate process.
